1. Introduction — Problem Statement & Motivation

⚠️ Physical Hardware Bottlenecks

  • Fragility & Wire Clutter: Breadboard connections suffer from loose jumpers, pin damage, and contact bounce that obscure logic.
  • No Pre-Simulation Safety: Accidental feedback wiring causes permanent IC burnouts and short circuits with no diagnostic warnings.
  • High Lab Cost: Discrete ICs, oscilloscopes, and logic analyzers require recurring institutional expenses.
  • Opaque Internal States: Probing 50+ intermediate pins physically is slow and error-prone.

💡 The Software Solution & Need

  • Graph-Theoretic Modeling: Digital circuits are mathematically represented as Directed Acyclic Graphs (DAGs).
  • Algorithmic Pre-Validation: Tarjan's 3-colour DFS detects circular feedback loops before execution, preventing infinite loops.
  • Topological Scheduling: Kahn's BFS orders gate evaluations so inputs are always calculated before gate execution.
  • Dual Architecture: Zero-dependency C++17 engine + interactive HTML5 Canvas drag-and-drop web EDA interface.

2. Literature Survey — 3 Research Papers Analyzed

1. Kahn's Topological Sort (1962) — Communications of the ACM, 5(11), 558–562
• Contribution: In-degree BFS queue algorithm for linear-time \(O(V+E)\) ordering of DAGs. Used for gate scheduling.
⚠️ Drawbacks: (1) Silent failure on cycles (queue empties without identifying cycle nodes); (2) Arbitrary tie-breaking; (3) Static re-sort on wire changes.
2. Tarjan's DFS Framework (1972) — SIAM Journal on Computing, 1(2), 146–160
• Contribution: Linear-time \(O(V+E)\) Depth-First Search with back-edge classification. Used for 3-colour cycle detection.
⚠️ Drawbacks: (1) Recursive call-stack overflow on deep circuits; (2) Rejects all feedback, prohibiting valid sequential logic (latches); (3) No evaluation levelization.
3. Tarjan's Union-Find (1975) — Journal of the ACM, 22(2), 215–225
• Contribution: Proved \(O(m \cdot \alpha(n))\) bound with path compression & rank. Used for wire-net equivalence management.
⚠️ Drawbacks: (1) Irreversible merges (cannot disconnect/split wires); (2) Lacks signal directionality (undirected sets only); (3) Overhead for small circuits.

4. Algorithms — Cycle Detection & Topological Sort

Tarjan's 3-Colour DFS Cycle Check \(O(V+E)\)

procedure HAS_CYCLE_DFS(u, color[], graph):
    color[u] ← GRAY // Active in recursion stack
    for each v in graph.adjList[u] do:
        if color[v] == GRAY then
            return TRUE // Back-edge = Cycle!
        if color[v] == WHITE then
            if HAS_CYCLE_DFS(v, color, graph) then
                return TRUE
    color[u] ← BLACK // Done
    return FALSE

procedure HAS_CYCLE(graph):
    color ← array of size V with WHITE
    for i ← 0 to V - 1 do:
        if color[i] == WHITE then
            if HAS_CYCLE_DFS(i, color, graph) then
                return TRUE
    return FALSE

Kahn's BFS Topological Sort \(O(V+E)\)

procedure TOPOLOGICAL_SORT(graph):
    inDegree ← array of size V with 0
    for u ← 0 to V - 1 do:
        for each v in graph.adjList[u] do:
            inDegree[v] ← inDegree[v] + 1

    queue Q ← empty FIFO queue
    for i ← 0 to V - 1 do:
        if inDegree[i] == 0 then
            Q.push(i) // Seed Primary Inputs

    order ← empty list
    while Q is not empty do:
        curr ← Q.pop()
        order.append(curr)
        for each v in graph.adjList[curr] do:
            inDegree[v] ← inDegree[v] - 1
            if inDegree[v] == 0 then
                Q.push(v)
    return order

4. Algorithms — Gate Evaluation & Truth Table

Gate Boolean Evaluation \(O(\text{fan-in})\)

procedure EVALUATE_GATE(gate, allGates):
    switch gate.type:
        case AND:
            res ← 1
            for inId in gate.inputGateIds:
                res ← res & allGates[inId].val
            gate.outputValue ← res
        case OR:
            res ← 0
            for inId in gate.inputGateIds:
                res ← res | allGates[inId].val
            gate.outputValue ← res
        case NOT:
            gate.outputValue ← !allGates[gate.inputs[0]].val
        case XOR:
            res ← 0
            for inId in gate.inputGateIds:
                res ← res ^ allGates[inId].val
            gate.outputValue ← res
        case NAND, NOR, XNOR:
            gate.outputValue ← !(AND / OR / XOR logic)
        case OUTPUT:
            gate.outputValue ← allGates[gate.inputs[0]].val

Exhaustive Truth Table \(O(2^N \cdot (V+E))\)

procedure GENERATE_TRUTH_TABLE(circuit):
    inputs  ← all gates where type == INPUT
    outputs ← all gates where type == OUTPUT
    N ← inputs.size()
    totalRows ← 2^N

    for combo ← 0 to totalRows - 1 do:
        // 1. Bitwise extraction for Primary Inputs
        for i ← 0 to N - 1 do:
            bitPos ← N - 1 - i
            inputs[i].val ← (combo >> bitPos) & 1

        // 2. Full simulation in Topo Order
        SIMULATE(circuit, verbose = false)

        // 3. Record output row
        printRow(inputs.values, outputs.values)

    // Complete functional verification in <1 ms
